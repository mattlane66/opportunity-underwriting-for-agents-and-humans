# Assurance Evaluations

`assurance-cases.json` defines the minimum methodological failure cases the v0.1 implementation must resist.

The deterministic test suite does not pretend to evaluate full LLM research quality. It checks that the repo's state/validation contract refuses the specific forms of rigor theater that can be made machine-checkable: arbitrary SOM, unsupported CAC, attention promoted to demand, top-down-only TAM, pool collapse, hidden unknowns, buried fatal gates, maturity-context blindness, ambiguous CAGR, and confirmation-only search.

Future model-runtime evaluations can use the same cases as behavioral prompts and score the artifacts the agent actually writes.
